# 웹킷으로도 같은 표 (2026-10-23 · 마스터 09:05 "다음: 웹킷으로도 같은 표")

## 무엇을 쟀나

`scripts/master-click.cjs` **그대로** 다 — 마스터 것이라 한 줄도 고치지 않았다. 그것을
**크로미움과 웹킷 둘에** 돌리고 표를 나란히 놓는 틀만 B 가 만들었다:
`samples/click_engines.js` (릴레이는 진짜 `wrangler dev --local`, 폰 폭 390px).

```
node samples/click_engines.js            # 둘 다
node samples/click_engines.js --only=webkit --shots
```

왜 웹킷인가: 아이폰 손님은 **사파리 그대로가 기본**이다(대표님 10-22 19:10 실기 합격).
그러면 손님 화면이 도는 곳은 웹킷인데, 10-22 표는 크로미움만 쟀다.

### 갈린 줄 넷 — 전부 **🎤 받아쓰기** 하나에서 나온다

| 줄 | 크로미움 | 웹킷 |
|---|---|---|
| 🎤 가 스스로 켜졌다 (원고 0) | PASS | FAIL |
| 🎤 / 🎤 끄기 | PASS | FAIL (안 보인다) |
| B 강사 진행 🎤 | PASS | FAIL (안 보인다) |

**까닭은 쟀다 — 짐작이 아니다**(MISTAKES #8). 두 엔진의 강사 화면에서 그대로 물었다:

```
chromium : SpeechRecognition=있음 · webkitSpeechRecognition=있음
webkit   : SpeechRecognition=없음 · webkitSpeechRecognition=없음
```

화면은 **맞게 움직였다** — `applyMicVisibility()` 가 받아쓰기가 없으면 🎤 칸을 숨기고
「이 브라우저는 받아쓰기를 못 한다」를 띄운다. 즉 이 넷은 화면 결함이 아니라 **플레이라이트
웹킷 빌드에 받아쓰기가 없는 것**이다.

⚠ 여기서 **멈춘다**: 플레이라이트 웹킷은 애플 사파리가 아니다. 진짜 아이폰 사파리에
받아쓰기가 있는지는 **이 PC 에서 잴 수 없다**. 그래서 "사파리에서도 된다"고 적지 않는다.
다만 강사는 보통 PC(크롬·엣지)이고, 손님 쪽 단추는 웹킷에서 **하나도 빠짐없이 통과**했다.

**마스터께 — 바꿀 것 하나** (`master-click.cjs` 는 마스터 것이라 B 가 고치지 않았다):
「크롬으로 열기」처럼 🎤 세 줄도 **웹킷에서는 N/A** 로 세면 표가 참이 된다. 지금은 고칠 것이
없는 줄 셋이 웹킷에서 영원히 붉다.

### 양쪽 다 붉은 줄 하나 — 「서버 번역」 단추

`B 손님 | 서버 번역 — 안 보인다` 는 **두 엔진 다** 붉다. 이것도 쟀다:

```
guest_tr_plan plan=server me=en browser=ko from=ko · canBrowser=false
```

이 PC 의 브라우저 말은 **한국어**다. 손님이 고른 말은 영어다. 브라우저 번역은 **브라우저
말로만** 한다 — 그러니 이 폰은 처음부터 **서버 번역 길**이고, 「서버 번역으로」 단추는
*브라우저가 번역해 줄 수 있을 때* 길을 바꾸라고 내는 것이라 **안 뜨는 것이 맞다**.

10-22 마스터 표에서 이 줄이 통과였던 것은 그 기계의 브라우저 말이 영어였기 때문이다 —
**화면이 바뀐 것이 아니라 재는 기계의 말이 다르다.** 이 줄 하나는 기계의 언어 설정에
따라 갈린다.

## 웹킷이 **찾아낸 진짜 결함** — 띠 글자가 안 보였다

웹킷은 "이 언어는 음성이 없다"고 답해서 **음성 없음 띠가 실제로 떴다**. 크로미움은 안 떴다.
그 사진에 **노란 바탕에 노란 글씨**가 찍혔다.

| 띠 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 음성 없음 `#voice-notice` | 글자 `#fef08a` — **1.05:1** | `--warning-ink` — **4.9:1** |
| 브라우저 번역 안내 `#tr-notice` | 글자 `#bae6fd` — **1.09:1** | `--text` — **13.7:1** |
| 쉬는 시간 `#break-band` | `#b45309` — 4.49:1 (AA 턱밑) | `--warning-ink` — **5.3:1** |

까닭: 10-22 에 배색을 밝게 바꿀 때 이 띠들만 **어두운 배색 때 글자색**으로 남았다.
왜 안 걸렸나: `test:a11y` 는 "**보이는 것만** 잰다"인데 띠는 평소 `display:none` 이고,
게다가 띠가 든 `#chat-screen` 자체가 들어가기 전에는 숨어 있다. **그물이 내 편을 들었다.**

고침은 둘이다:
1. 색을 토큰(`--warning-ink`·`--text`)에서 받는다 — 값의 정본은 `/common/theme.css`.
2. `samples/a11y_test.js` 가 **띠를 띄워 놓고**(대화 화면까지 열어서) 잰다. 되돌림 실증을
   하나 더 뒀다: 옛 색 `#fef08a` 로 되돌리면 **1.04:1 로 붉어진다**.
