# 레이팩을 **손님 브라우저에서** 돌린다 — 재는 자리와 숫자 (장부 63 · 2026-10-28)

장부 63: *손님은 전부 웹. 언어를 고를 때 레이팩(ko→X 한 파일)을 브라우저에 받아 **폰 안 번역**.*
마스터 NOW 10-28 11:35: **측정 먼저**, 손님 페이지에 붙이는 일은 그 뒤.

재는 자리: **<https://raytok.kr/web/raypack-probe/>** (사이트 안 링크 0개 — 주소를 아는 사람만 연다)

## 1. 어떻게 도나 — 네 걸음

| 걸음 | 무엇 | 쓰는 것 |
|---|---|---|
| ① 목록 | `…r2.dev/index.json` 에서 말 목록 | `fetch` |
| ② 받기 | `…r2.dev/<파일>.rtpack` (48~70MB) · 진행 막대 · **크기·sha256 맞춰 본다** | `fetch` + `crypto.subtle` |
| ③ 풀기 | zip 을 브라우저 안에서 | `web/vendor/fflate.min.js` (MIT) |
| ④ 번역 | Worker 에서 **ko→en→X 두 다리** | `web/vendor/bergamot/` — `@browsermt/bergamot-translator` v0.4.9 (MPL-2.0) |

- **서버로 글이 가지 않는다.** 받은 뒤에는 인터넷이 없어도 번역된다(저장해 두면 두 번째부터 즉시).
- **CDN 에 기대지 않는다** — bergamot WASM(5.2MB)도 fflate 도 **이 사이트에 같이 올려** 둔다.
- 팩에서 모델을 꺼내 주는 뒷배가 `RaypackBacking` 이다(`web/raypack-probe/probe.js`).
  팩 안 꼴은 엔진 약속 그대로다: `manifest.json` + `mt/<짝>/{model,lex,vocab}.bin`
  (`en→ja`·`en→ko` 두 짝만 어휘가 **두 벌** — 그것도 받는다).
- **`ko→en` 전용 팩은 없다. 일부러다** — 1단 `mt/ko-en/` 이 **모든 팩 안에** 들어 있다.
  그래서 `en` 을 잴 때는 **가장 작은 팩을 운반 팩**으로 쓰고 화면에 그렇게 적는다.

## 2. R2 CORS — **이미 열려 있다**(10-28 에 확인했다)

버킷 `raytok-packs` 가 돌려주는 머리글을 직접 봤다:

| 물어본 주소 | `Access-Control-Allow-Origin` |
|---|---|
| `https://raytok.kr` | **`https://raytok.kr`** · OPTIONS 204 · `GET, HEAD` 허용 |
| `https://www.raytok.kr` | **허용 안 됨** |
| `http://localhost:…` · 그 밖 | 허용 안 됨 |

⚠ **`www.` 는 막혀 있다.** 손님이 `www.raytok.kr` 로 들어오면 팩을 못 받는다 —
붙이기 전에 **`www` 를 `raytok.kr` 로 넘기든가** CORS 에 한 줄 더하든가 해야 한다(대표님 손).
⚠ 그래서 이 PC(`localhost`)에서는 **직접 못 받는다** — 올리기 전 시험은 `?base=/r2` 로
우리 서버가 대신 받아 주는 길을 썼다.

> **판정선(마스터): 크롬 한 문장 ≤ 1초 → 넉넉히 넘었다.** 폰에서 **첫 문장 177~227ms · 데운 뒤 41~79ms**.
> ★ **폰이 PC 보다 빨랐다.** 폰이 좋아서가 아니라 같은 때 PC 에서 **프리미엄 7B 모델이 돌고 있었다** —
> 그래서 PC 줄은 **「바쁜 PC」 값**으로 읽고, 기기 값으로는 **폰 줄**을 본다.
> 「첫 번역까지」(폰 1~1.9초)는 **엔진 띄우기 + 모델 싣기**를 다 포함한 값이다 — 말 고른 뒤 **한 번만** 든다.
> ⚠ **받는 시간은 그물 값이고 기기 값이 아니다** — 같은 팩이 같은 날 19MB/s 와 1.1MB/s 로 다 나왔다.
> 기기를 가리는 숫자는 푸는 시간·첫 번역까지·한 문장이다.
> **두 번째 열 때 0.1초**는 Cache Storage 에서 꺼낸 값이다(둘째 방부터는 기다림이 없다).
> 메모리 **125MB** 는 60MB 팩을 풀어 들고 있는 값이다 — 탭을 닫으면 돌려준다.

**폰은 어떻게 쟀나**(숫자를 베끼지 않았다): 대표님이 잠금을 한 번 풀어 주신 뒤 USB 로
`?auto=en,vi` 를 띄워 **손가락 없이** 돌리고, **DevTools(`adb forward`)로 표를 그대로 읽었다.**
끝나고 **내가 연 탭을 닫고 화면 설정을 되돌렸다**(D-32 · `stayon=false` 확인).

## 3.5 ★ 아이폰 — **iOS 15 에서는 안 뜬다. 16.4 부터다** (10-28 14:20, 기기가 직접 말했다)

대표님 아이폰(**iOS 15.0** · Safari 604.1)에서 쟀다. 받기 48MB **100%** · 푸는 것 3초까지 **다 됐고**,
**엔진에서** 멈췄다. 고친 판(v3)이 그 까닭을 글로 남겼다:

```
브라우저 살피기 — WASM 있다 · SIMD **안 된다** · 작업자 있다 · 저장 된다
엔진이 오류를 냈다: WebAssembly.Module doesn't parse at byte 79:
  invalid opcode 253, in function at index 4096
```

**`opcode 253` = `0xFD` = WASM SIMD 머리 바이트**다. 한 줄에 둘이 같이 증명됐다:
① 이 기기에 **SIMD 가 없다** ② bergamot 의 wasm 이 **실제로 SIMD 를 쓴다**(이 전까지는 「확인 못 했다」로
적어 두었던 자리다 — 이제 확인됐다). 사파리는 **WASM SIMD 를 iOS 16.4 부터** 한다.

| 기기 | 받기 | 풀기 | 엔진 | 판정 |
|---|---|---|---|---|
| 아이폰 **iOS 15.0** | ✅ 48MB | ✅ 3초 | ❌ `invalid opcode 253` | **안 된다** |
| 안드로이드 Chrome 155 | ✅ | ✅ | ✅ | **된다**(한 문장 41~79ms) |
| PC Chromium 152 | ✅ | ✅ | ✅ | **된다** |

⇒ **붙일 때 규칙**: 브라우저가 SIMD 를 하면 레이팩으로, 아니면 **지금 쓰는 길(서버 번역)로 내려간다.**
재는 장은 이제 SIMD 가 없으면 **48MB 를 받기 전에 멈추고** 그 까닭과 갈 길을 적는다(v4).
⚠ **iOS 16.4 이상 아이폰은 아직 못 재 봤다** — 「뜨기만 하면 붙인다」는 판정은 그 기기가 생겨야 끝난다.
⚠ SIMD 없는 bergamot 판이 따로 있는지는 **안 알아봤다**(있으면 옛 아이폰도 살릴 수 있다).
